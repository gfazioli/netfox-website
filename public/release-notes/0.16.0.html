Netfox 0.16.0

Release notes

Netfox checks every device by connecting to it across the network. That is the right way to check a printer, a NAS or a phone — and the wrong way to check the Mac you are sitting at. This release closes that blind spot, and fixes a port state that had been reported backwards.

Local Services

A new tab on This Mac lists every port your Mac is accepting connections on. It does not probe anything: it asks the system directly, which is the only way to see the whole picture.

  • The ports nothing else could see. A development server on 127.0.0.1:3000 genuinely refuses connections from anywhere else, so a network check reports it closed — accurately, and uselessly. Those listeners are now listed, grouped apart from the ones the rest of your network really can reach.
  • Names instead of numbers. 3000 says nothing; shop.local:3000 says which project it is. If a listener's address has names pointing at it on your Mac, they are shown beside the port. This is where a list of numbers turns into a list of the local sites and side projects you set up months ago and forgot were still running.
  • Two groups, each explained. Only on this Mac and Reachable from the network, with an (i) beside each that explains in plain English what the distinction means and when it is worth a second look.
  • Nothing to grant. No password, no permission prompt, no helper. Your own listeners come back complete.

Fixes

  • A closed port now says closed. A port that actively refuses a connection was being classified as filtered, as though something were standing in the way. Closed and filtered mean different things — nothing listening, versus something blocking — so this was a wrong answer on every scan. It also made scans slower: a refusal is an immediate answer, and it was being waited out to the full timeout instead.
  • Two devices with the same name stay two devices. When one device took over an address another had been using and answered to the same name, Netfox could fold the two into a single row carrying the wrong hardware. They now stay apart when their hardware shows they are genuinely different — while a phone that rotates its address between sightings still stays one device, which is the failure people actually notice.

Privacy

Demo Mode covers the new list. Process names, their numbers, any names of your own and a specific bound address are all hidden with one keystroke, so a screenshot of what is running on your Mac never gives away what you have installed.

Under the hood

  • The framework test suite has rejoined the gate. It had been running 64 of its 148 tests, because a failed assertion left a short array that the next line indexed and killed the runner. Both numbers are now 148, and the run is 452 + 148. The refused-port defect above is what the broken suite had been hiding — nobody could see it while it was not running.
  • Identity matching moved out of the discovery actor into a pure, testable type. Exercising it previously meant starting real network browsers, which collapsed the suite from 430 tests to 39 — so the rule at the centre of what the app claims to do was effectively untestable.
  • The listener parser reads the whole of 127.0.0.0/8 as loopback rather than only 127.0.0.1, so an lo0 alias is classified correctly.
  • Process names are no longer truncated to nine characters.
  • The interface, including every new string and both explanations, is translated into Italian, French, German, Spanish, Portuguese and Dutch. Catalog coverage is 735/735 on all six.

Install

Download the DMG, drag Netfox to Applications. Existing installs update themselves.

Requirements

macOS 15.6 or later. Universal (Apple Silicon + Intel). Signed and notarized.
