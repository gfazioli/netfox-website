Netfox 0.17.1

Release notes

A patch, and the whole of it is one idea: a device should look like itself everywhere, and stay looking like itself.

One device, one icon

The same device could carry a different icon in the device list, in its own alerts, in its History window and in the tag editor — and could change between launches, with no setting touched and no code changed.

Three separate causes, all now closed:

  • The stored category was decided by whichever discovery answered first. A device advertising two service types that mean different things — a HomePod advertises both an audio one and a display one — got whichever arrived first. The browsers run concurrently, so "first" was genuinely random between launches. The category is now decided by what the device says about itself, and where the evidence does not reach, it stays put rather than flipping.
  • Three surfaces read the raw stored value instead of the one the list shows. So a router promoted correctly in the list showed a question mark in the History window opened from that very row, and the tag editor offered "Auto-detect (Unknown)" beside a router icon.
  • An alert kept only half its device. The snapshot dropped the model and the advertised services, so an alert re-read after a restart had only the device's name to go on — and looked different from the same alert an hour earlier.

A product name instead of a code

Some devices answer the "what are you?" question with an internal board code rather than a product identifier, and which of the two you get depends on which service you ask. Netfox now prefers the one it can name: where it recognises the code, the Model row reads Apple TV instead of a string of letters and digits.

The timeline explains a change instead of just making it

A device that re-identifies itself — a new category, a better model — used to have its row change quietly under you, with nothing in its history to account for it, while an address change of the same significance got its own entry. Those changes are now recorded like any other.

Under the hood

  • The test gate crashed about one run in three, and the cause was not what it looked like. A crash report showed ten database connections opening in one process with two of them inside the same table-creation path — an intra-process race, not the shared-file conflict every other failure of this shape has been. Serialising that construction fixed it: ten consecutive clean runs against a prior rate near one in three. The wrong diagnosis is kept in the code, because the fix that followed from it would have made the race more frequent while looking like a repair.
  • The release pipeline now refuses to sign with the wrong toolchain. The tool that signs an update and the framework that verifies it on your Mac were never tied together, and on the build machine they had drifted apart. Harmless so far, and exactly the kind of thing that fails after the download rather than before it.
  • A window that was ordered out is now closed properly. The suspected leak did not reproduce when measured, and that is recorded too — but dropping the only reference to a window nothing can close afterwards is wrong on its own terms.
  • Six languages, as always: every new string is translated into Italian, French, German, Spanish, Portuguese and Dutch.

Install

Download the DMG, drag Netfox to Applications. Existing installs update themselves.

Requirements

macOS 15.6 or later. Universal (Apple Silicon + Intel). Signed and notarized.
