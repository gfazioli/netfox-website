Netfox 0.17.0

Release notes

Two questions this release answers without a terminal and without a router admin page: is my Wi-Fi the problem, and what is holding that port.

Is my Wi-Fi the problem?

The Wi-Fi tab already showed you the numbers. It did not tell you what they meant. Open the network you are connected to and the panel now answers the question in a sentence.

  • A verdict, in plain English. One of four: the Wi-Fi looks fine, the channel is busy, the signal is weak, or both at once. Which one it is decides what you should actually do — a busy channel and a weak signal call for opposite moves, and the numbers alone never said which you had.
  • The three numbers behind it. How many networks share your stretch of spectrum, how many of them are close enough in strength to compete with you for the channel, and your signal-to-noise ratio. The middle one is the one that decides the verdict, and it is deliberately not the same as the first: an access point far below yours overlaps your spectrum on paper without ever holding you up, so counting it would call a perfectly good link crowded.
  • A quieter channel, when one exists. Netfox names it, and judges the candidate by the width your access point would carry there rather than by the channel number alone.
  • Wide channels counted as what they are. An 80 MHz access point on channel 36 is using 36 through 48. A "quiet" channel inside that range is not quiet, and both the occupancy figures and the suggestion account for it.
  • The rest of the band, at a glance. A row of chips shows each channel in your band with how many networks sit on it and how many reach into it from a neighbouring block. Yours is marked.
  • It stays quiet when it cannot tell you honestly. A band it barely saw gets no channel suggestion. A "quieter" channel has to be quieter by a real margin, not by one access point. And where macOS gives no noise reading, the signal half is reported as unknown rather than assumed to be good — a verdict that read a missing measurement as a clean bill of health would be worse than no verdict.

An (i) beside each part explains how it was worked out, for when the answer is surprising enough that you want to see the reasoning.

A hidden network is now explained

Hiding a network's name is widely believed to be a security measure. It is not one: the devices that already know the network broadcast its name while they look for it, so anything nearby can learn it by listening. Netfox used to label these networks and leave it there. It now says what the label means — and counts them toward the congestion picture, because an access point that withholds its name occupies spectrum exactly like one that publishes it.

Freeing a port on This Mac

Netfox would show you that something was holding port 3000. The next step was still a terminal. Each row on Local Services now has an action that asks that process to quit.

  • It asks first. The polite request, so a development server can save what it was holding. If the process ignores it, Netfox offers to force the matter — and only then, because forcing loses unsaved work.
  • The whole family, not the first one. A server that runs a worker per core is one row here and several processes behind it. All of them are asked, starting with the one that opened the socket. Asking only the first would leave the port held for no visible reason.
  • A refusal explains itself. A listener owned by another user or by the system needs privileges Netfox does not have and does not ask for. Those rows say so when you press them, rather than being a dead control.
  • It re-checks before it acts. A row is a snapshot of a moment that has already passed, and process IDs get reused. Netfox reads the port again immediately before sending anything, and stops if what it finds is not what you asked about.

The action is unavailable while Demo Mode is on, since Demo Mode replaces process names with placeholders — a confirmation dialog naming something that is not the real target would be worse than no button at all.

More devices say what they are

The list of services Netfox recognises grew, after measuring what a real network actually answers for. One of the additions closes a blind spot rather than adding a nicety: HomeKit accessories announce themselves over the Accessory Protocol, which Netfox was not looking for — so they arrived as Unknown while the label for them existed and was unreachable. Screen sharing, scanning (both the modern and the older spelling that multifunction printers use), Matter and Spotify Connect are recognised and named too.

Under the hood

  • The competing-neighbour threshold is measured, not chosen. On a real dense environment — 33 access points visible at 5 GHz, median −85 dBm against a −58 dBm link — the count of competing neighbours sat flat at 2 all the way out to 15 dB and only then climbed, reaching 11 by 25 dB. 15 dB is where the plateau ends, which is why that is the window.
  • Nothing new is probed, and nothing new is asked for. Occupancy, overlap and the verdict are all computed from the scan the Wi-Fi tab already performs. No new permission, no new traffic, no extra battery.
  • The quit path decides on fresh data. Eligibility is re-evaluated against the row read a moment before the signal is sent, not against the row on screen; a process that has become ineligible in between is refused rather than acted on. It then waits for the process to actually be gone rather than reporting success on a delivered signal.
  • An API with tests and no callers was deleted. identitySummary had coverage and zero call sites — the tests were proving that unused code kept working.
  • The test gate now refuses to run while the app is open. The app-hosted test bundle is a second process on the same stores, and the running app dies. It waits for the stores to be released instead of crashing the app that holds them.
  • Six languages, in step. Every new string is translated into Italian, French, German, Spanish, Portuguese and Dutch. Coverage is 817/817 on all six, plus 82/82 in the framework catalog.
  • 475 + 215 tests, green.

Install

Download the DMG, drag Netfox to Applications. Existing installs update themselves.

Requirements

macOS 15.6 or later. Universal (Apple Silicon + Intel). Signed and notarized.
