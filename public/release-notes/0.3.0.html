Netfox 0.3.0

Release notes

🛡 Security tool gets a full inventory

  • Service Inventory — By Service view — the Security tab gains a toggle: see your network grouped by what services are exposed (Plex, nginx, Telnet, …), not just which devices have which ports open. Click a row to drill into the devices contributing each service.
  • HTTP service identification — when a device exposes a web port, Netfox grabs the Server: header + page title and surfaces them inline ("Plex Media Server", "nginx/1.24", "HP printer admin"). Opt-in from Settings → Service identification; outgoing HEAD request, LAN-only, never leaves your network.
  • UPnP / SSDP discovery — catches the devices Bonjour doesn't see: consumer routers, smart TVs, NAS units, casting boxes. Runs on a 120-second poll, joins the multicast group as a receiver — no extra permissions required.

🚨 Three new alert kinds (all opt-in)

  • Port opened on a known device — fires when a previously closed or filtered port comes back as open ("Port 80 (HTTP) opened on the BRAVIA TV"). Uses the same per-(device, port) dedup as new-device alerts.
  • New service identified — fires the first time we fingerprint a web service on a port ("Plex Media Server detected on Living-Room-iMac"). Pairs with Service identification above.
  • Risky new device arrived — fires when a device first seen in the last 48 hours scans with a high-severity finding ("Telnet exposed on new device guest-laptop"). Pairs with the existing new-device alert.

🤫 Per-device mute

Right-click any device → Mute Alerts. Silences every alert kind for that one device (new-device, returned, port-opened, new-service, risky-arrival) without hiding the row. Useful for guest phones that keep tripping the returned-after-absence alert and for acknowledged-but-noisy routers. A small bell-slash indicator next to the device name keeps the silence discoverable.

🌐 VPN awareness

A VPN chip appears in the Home Public IP card and the Devices banner whenever the Mac is on a VPN tunnel. Makes "why is my public IP suddenly Frankfurt" answerable at a glance instead of a system-settings dive.

🪞 Tool renamed: Overview → Devices

The "Overview" tool is now "Devices". Matches the existing KPI on Home and the natural shorthand the rest of the UI was already using.

🎨 UI polish

  • Demo Mode now masks device names + MAC suffixes in the alerts inbox + history sheet too — earlier the masking only applied to the device list, leaving real hostnames visible to screenshots taken from the bell.
  • Right-click → Copy on every identity row in the device detail (MAC, IPv4, IPv6) — the inline copy button stays, but the most natural macOS gesture now also works.
  • Wi-Fi list keeps the last known networks when macOS rate-limits the scan, instead of blanking to "No networks found" between successful ticks.
  • Devices tool renders full-width on first paint after a Wi-Fi → "View Devices" cross-link (was a compact island stuck mid-window).

🩹 Fixes

  • .portOpened / .newService / .riskyDeviceArrival no longer silently dropped when a device id is consolidated mid-probe.
  • Location permission prompt is more reliable on notarized installs under macOS 26 (added a documented requestLocation() call alongside the existing two triggers, plus a "Open Location Settings" escape hatch).
  • Demo Mode + sample data toggle now correctly re-injects sample alerts on launch, not just on Settings toggle.

🔬 Under the hood

  • 50+ new unit tests covering anomaly factories, service aggregation, banner parser truth-table, SSDP message parser, Wi-Fi scan resilience contract, and the consolidation rewrite map.
  • Persisted alert schema gains additive Optional columns so existing installs upgrade silently.
  • Sparkle's sign_update now invoked with the explicit --account Netfox flag in release.sh to disambiguate from co-resident keypairs.
